Day-ahead solar power forecasting

Question

On day D, forecast the plant's power for each of the 96 fifteen-minute blocks of day D+1. One row is one block of D+1; the target is its power. The forecast is assumed to be made after day D ends, so all of day D is known. Each model is tested with three sets of inputs, each adding one source of information:

  • Case 1 — power at the same block on day D.
  • Case 2 — Case 1 plus day D's weather (sunlight, module and air temperature, wind). The realistic case.
  • Case 3 — Case 2 plus day D+1's measured weather. Acts as a perfect weather forecast, so it is an upper bound, not a real forecast.

Scope of the claim: one plant and one winter (Oct 2025 – Feb 2026). The results describe this plant in this season and may not carry over to other seasons or sites.

Data

Plant SCADA and on-site weather-station data supplied by the course instructor: 15 Oct 2025 – 14 Feb 2026, 123 days × 96 blocks = 11,808 rows, with no missing timestamps or cells. The data is not redistributed: the repository excludes it, and this page shows power only as a percentage of capacity.

Cleaning

  • 27 Nov 2025: 07:45–16:30 had been copied from another day; replaced by the average of 26 and 28 Nov.
  • 14 Jan 2026: power stuck at 12.80 MW from 13:45–16:30; re-estimated from sunlight and module temperature.
  • Night sunlight read 1.12 W/m² (one sensor step) instead of 0; set to 0.
  • Both repaired days are in the training period, so every validation and test score uses real measurements.

Methods

ModelIdeaWhy it is here
PersistenceTomorrow's block = today's blockThe standard naive baseline; skill is measured against it
7-day averageMean of the same block over the last 7 daysA second baseline that smooths out one-off cloudy days
Linear regression (MLR)Weighted sum of inputs, least squaresPower is roughly linear in sunlight; the simplest learning model
Ridge / Lasso / Elastic NetMLR with an L2, L1 or mixed penalty on coefficientsThe inputs are strongly correlated (yesterday's power and sunlight, the two temperatures); Lasso can also drop useless inputs
Random Forest300 regression trees on bootstrap samples, averagedTrees can bend to follow the plant's midday plateau; averaging reduces variance
AdaBoost (AdaBoost.R2)Small trees added one at a time, focusing on rows earlier trees got wrongReduces bias; comparing it with Random Forest shows whether errors come from bias or variance

Assumptions: linear models assume power changes in a straight line with each input — not true at the midday plateau (see the Data plot). Tree models assume nothing about shape but can memorise the training period. Every learning model is fitted on training data only; inputs to the penalised models are standardised with a scaler fitted on training data only. Forecasts are clipped to 0–21.5 MW.

Evaluation

  • Chronological split by target day: train 15 Oct – 14 Jan (92 days), validation 15 Jan – 7 Feb (24 days), test 8 – 14 Feb (7 days). Models only ever learn from the past; test is used once, at the end. A random split would put later days in training and let the model "see the future".
  • Daytime only (07:00–18:15): at night every model is trivially right, which would hide real differences.
  • Metrics as % of the 21.5 MW capacity: MAE, RMSE, R², and the share of blocks within ±7% of capacity (the regulator's tolerance). Errors are divided by capacity, not by actual power, because actual power is near 0 at sunrise and percentage errors such as MAPE would explode.
  • Skill = 1 − RMSEmodel / RMSEpersistence: 0 means no better than "tomorrow = today". The 90% interval comes from resampling the days 1,000 times; a model is clearly better only if the whole interval is above 0.

What the results say

  • With only yesterday's data (Cases 1–2), nothing reliably beats persistence. Small validation gains turn negative on the test week, and every test interval includes zero or falls below it.
  • Penalties did not help. Ridge, Lasso and Elastic Net score within about 1% of plain linear regression; Lasso only drops the wind inputs.
  • With tomorrow's weather (Case 3), the tree models pull ahead because they can follow the plant's midday plateau. Random Forest is the only model whose test gain is clearly above zero.
  • R² is high for every model (88–97%), even persistence, because the daily sun curve explains most of the variation. It ranks models much like RMSE but separates them far less, so skill and RMSE are the better guides.

Which inputs does the best model use?

Random Forest, permutation importance on validation: how much the validation RMSE rises (% of capacity) when one input is shuffled. In Case 3 almost everything comes from tomorrow's sunlight; wind adds nothing in either case. This shows what the model relies on, not what causes the plant's output.

Errors and limitations

  • Weather changes are the main error: 26–27 Jan are the hardest days for every model without tomorrow's weather.
  • Linear models over-forecast at midday, because the plant levels off while a straight line keeps rising.
  • Overfitting: in Case 2, Random Forest fits training far better than validation and loses to persistence on test.
  • One plant and one winter; the test set is only 7 calm days, so its intervals are wide.
  • Case 3 uses measured weather; a real forecast would use weather predictions, which have their own errors.
  • The forecast is assumed to be issued after day D ends; real schedules are submitted earlier.
  • Wind direction is on an unknown 0–40 scale and was used as recorded.
  • These are forecasts, not causes: which inputs a model relies on says nothing about what drives the plant.

Conclusion

In a clear winter, "tomorrow = today" is very hard to beat with yesterday's data alone. The useful gain comes from knowing tomorrow's weather, and from a model that can follow the plant's non-linear midday plateau: with both, Random Forest cuts the error by about a fifth on the test week. A practical next step is to replace the measured future weather with real numerical weather forecasts.

Reproduce

How to rerun the project and get the same numbers:

  1. src/build_clean_winter.py builds the clean dataset from the raw monthly exports.
  2. Run each model notebook in src/ (any order).
  3. Run src/summary.ipynb last; it re-scores every model and writes the data this page reads.

Setup, data access, split details and the AI-use disclosure are in the repository README.

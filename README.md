# Day-ahead solar power forecasting (ES 335 course project)

Can we forecast tomorrow's power at a 21.5 MW solar plant, block by 15-minute block, better than simply
assuming *tomorrow = today*, and how much does weather information help?

- **Live website:** https://dhanraj-24110106.github.io/solar-forecasting-es335/
- **Author:** Dhanraj Visapara (24110106)
- **Course:** ES 335 · Machine Learning

Eight models (persistence, 7-day average, MLR, Ridge, Lasso, Elastic Net, Random Forest, AdaBoost) are compared under
three sets of inputs: yesterday's power (Case 1), plus yesterday's weather (Case 2), plus tomorrow's measured weather
(Case 3, an oracle upper bound). Every choice and its reason is logged in [`DECISIONS.md`](DECISIONS.md).

All notebooks are committed **with their outputs**, so every table and figure can be read on GitHub without rerunning.

Headline: with only yesterday's data (cases 1–2) no model is clearly better than persistence on the test week; with
tomorrow's measured weather (case 3) Random Forest is, with skill +19.6% (90% interval +3.5 to +38.6%).

## Exact preprocessing

`src/build_clean_winter.py` does exactly this, and nothing else:

1. Reads the raw monthly power, weather and module-temperature exports and joins them on timestamp; keeps
   15 Oct 2025 00:00 – 14 Feb 2026 23:45 and checks there are no missing timestamps or empty cells.
2. **27 Nov 2025, 07:45–16:30** (36 blocks): every column is replaced by the average of the same block on 26 and 28 Nov
   (the raw export had copied these blocks from 26 Nov).
3. **14 Jan 2026, 13:45–16:30** (12 blocks): power is re-estimated by a linear regression of power on GHI and module
   temperature fitted on daytime blocks of 7–13 Jan, capped at that day's own observed peak (the meter was stuck at 12.80 MW).
4. **Night GHI**: values of at most 1.125 W/m² when power is 0 are set to 0 (one step of sensor offset).

In the model notebooks: inputs are the same block on day D (and day D+1 weather in case 3); only daytime blocks
(07:00–18:15) are used; Ridge, Lasso and Elastic Net standardise inputs with a scaler fitted on training data only;
forecasts are clipped to 0–21.5 MW.

## Data access

The plant SCADA and weather-station data (Deon Energy 25.8 MWp / 21.5 MW AC plant, Surendranagar, Gujarat;
15-minute resolution) was provided by the course instructor. It is **not redistributed in this repository**.
To rerun everything, place the monthly exports at:

```
Data/Raw/Winter/Power/<Month>.csv        # TimeStamp, Act. Power (MW)
Data/Raw/Winter/Weather/<Month>.csv      # TimeStamp, W-GHI, W-AMBT, W-WDIR, W-WSPD
Data/Raw/Winter/ModuleTemp/<Month>.csv   # TimeStamp, W-MODT
```

for October 2025 – February 2026. The website only publishes power as a fraction of the plant's capacity.

## Reproduce the results

Run from the project folder:

1. `python src/build_clean_winter.py` — writes `Data/Clean/Winter_Clean.csv` (123 days, 11,808 rows). It repairs
   27 Nov 2025 (copied data) and 14 Jan 2026 (stuck power meter) and sets night-time GHI to 0.
2. Run every model notebook in `src/` (any order). AdaBoost takes about 11 minutes, Random Forest about 1.5 minutes,
   the rest a few seconds. To run them all and save their outputs:
   `cd src && for nb in persistence_baseline seven_day_average_baseline mlr ridge lasso elastic_net random_forest adaboost summary; do jupyter nbconvert --to notebook --execute --inplace $nb.ipynb; done`
3. Run `src/summary.ipynb` last. It writes `docs/data/*.json`, `results/splits.csv` and `results/metrics/summary_table.csv`.
4. Preview the site: `python3 -m http.server 8000 --directory docs`, then open http://localhost:8000.

**Split (by target day, chronological):** train 15 Oct 2025 – 14 Jan 2026 (92 days), validation 15 Jan – 7 Feb
(24 days), test 8 – 14 Feb (7 days). All tuning uses validation only; test is scored once.
**Scoring:** daytime blocks 07:00–18:15; MAE and RMSE as % of 21.5 MW, % of blocks within ±7% of capacity, R²,
skill vs persistence, and 90% bootstrap intervals over days. Random seeds are fixed (`random_state=42`).
